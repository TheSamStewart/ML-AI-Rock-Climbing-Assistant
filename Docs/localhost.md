# Running the app locally

This guide covers hosting the full stack on your own machine: Redis, the FastAPI backend, the Celery worker, and the Expo (React Native) frontend.

There are two ways to run it:

- **Docker Compose (recommended)** runs everything with one command.
- **Manual** runs each piece by hand, which is useful for debugging a single service.

## Architecture at a glance

| Service    | What it is                                  | Port |
|------------|---------------------------------------------|------|
| `redis`    | Celery broker/result backend and idempotency keys | 6379 |
| `api`      | FastAPI app (`backend/main.py`)             | 8000 |
| `worker`   | Celery worker (`backend/worker.py`) that runs hold detection and the Claude coaching call | none |
| `frontend` | Expo dev server (Metro) for the mobile app  | 8081 |

The mobile app calls the API at `http://<host>:8000`. It takes `<host>` from the Expo dev server address (`Constants.expoConfig.hostUri`) and falls back to `localhost`. This is why the LAN IP matters when you test on a physical phone (see [Testing on a physical phone](#testing-on-a-physical-phone)).

API endpoints:

- `POST /detect` runs hold detection on an uploaded image.
- `POST /analysis` starts a coaching analysis. It requires an `Idempotency-Key` header and returns 202 with a task id.
- `GET /analysis/{task_id}` polls the task state and result.

## Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) with Compose v2 (`docker compose`).
- The trained YOLO weights at `backend/models/best.pt`. The file is not generated by the app. Without it, hold detection fails. To use a different path, set `MODEL_PATH`.
- An [Anthropic API key](https://console.anthropic.com/) for the coaching LLM call.
- The **Expo Go** app on your phone (iOS or Android), or an emulator/simulator.
- An [Expo access token](https://expo.dev/settings/access-tokens), only if you run the frontend in Docker. It authenticates the CLI, which has no TTY to run `expo login`. Use the account that Expo Go on your phone is signed into.

Only for the manual route:

- Python 3.14 or newer and [uv](https://docs.astral.sh/uv/)
- Node.js and npm
- A local Redis 7 (or run just `docker compose up redis`)

## Option 1: Docker Compose

### 1. Create `.env`

Create a `.env` file in the repo root (Compose reads it automatically). It is gitignored, so don't commit it.

```env
ANTHROPIC_API_KEY=sk-ant-...
EXPO_TOKEN=your-expo-access-token
HOST_LAN_IP=192.168.1.50
```

| Variable            | Used by    | Purpose |
|---------------------|------------|---------|
| `ANTHROPIC_API_KEY` | `worker`   | Coaching LLM call |
| `EXPO_TOKEN`        | `frontend` | Lets Expo CLI authenticate without an interactive login |
| `HOST_LAN_IP`       | `frontend` | Your machine's real LAN address, passed to Metro as `REACT_NATIVE_PACKAGER_HOSTNAME` |

Inside the container, Metro only sees Docker's internal bridge IP. If it advertised that address, every API call from your phone would fail. `HOST_LAN_IP` overrides it.

To fill in `HOST_LAN_IP` automatically, run the helper script in the next step. Or find your IPv4 address with `ipconfig` and enter it by hand.

### 2. Set the LAN IP (Windows)

```powershell
powershell -File scripts/refresh-lan-ip.ps1
```

The script:

1. Detects your LAN IPv4 address. It skips loopback, link-local, Docker/WSL/VPN and other virtual adapters, and prefers Wi-Fi.
2. Writes it to `.env` as `HOST_LAN_IP`.
3. Recreates only the `frontend` container if the stack is already running. No image rebuild is needed.

### 3. Start the stack

```powershell
docker compose up --build
```

The first build is slow. The backend image installs `ultralytics` and its dependencies, and the frontend runs `npm ci` on first start. Later starts are much faster; run without `--build` unless a Dockerfile or dependency changed.

To run in the background, add `-d`. To follow one service's logs:

```powershell
docker compose logs -f frontend
```

The frontend container needs a TTY to print the Expo QR code. Compose sets `tty: true` for it. If you started with `-d`, view the QR code in the frontend logs.

### 4. Verify

- API docs: <http://localhost:8000/docs>
- Redis health: `docker compose ps` should show `redis` as healthy.
- Worker ready: `docker compose logs worker` should show `celery@... ready`.
- Frontend: `docker compose logs frontend` should show the Expo QR code and an `exp://<HOST_LAN_IP>:8081` URL.

### 5. Stop

```powershell
docker compose down        # stop and remove containers, keep Redis data
docker compose down -v     # also delete the Redis volume
```

### Live reload

- `backend/` is bind-mounted into the `api` and `worker` containers, and the API runs with `--reload`, so edits to the API take effect immediately.
- The **worker does not auto-reload**. After changing `worker.py` or `detection.py`, run:

  ```powershell
  docker compose restart worker
  ```

- The frontend source is bind-mounted, so Metro hot-reloads on save.
- Changing Python dependencies (`pyproject.toml`/`uv.lock`) needs `docker compose up --build api worker`.
- Changing `package.json` needs `docker compose up --build frontend`.

## Testing on a physical phone

1. Put your phone and PC on the **same network**. A guest network, a Wi-Fi extender on a different subnet, or a VPN can break this.
2. Make sure `HOST_LAN_IP` in `.env` matches your PC's current address on that network.
3. Open Expo Go and scan the QR code from the frontend logs, or enter the `exp://<HOST_LAN_IP>:8081` URL.
4. Allow Docker/Node through the Windows firewall for ports **8081** (Metro) and **8000** (API) on private networks. If the phone can't connect, this is the most common cause.

**Whenever your network changes** (new Wi-Fi, DHCP renewal, docking or undocking), Expo Go will report "Could not connect to server". Run `scripts/refresh-lan-ip.ps1` again to fix it. It takes seconds and doesn't rebuild anything.

If you're using an emulator or simulator on the same machine, `localhost` works and the LAN IP doesn't matter.

## Option 2: Manual (no Docker for the app)

Run these in separate terminals from the repo root.

### Redis

```powershell
docker compose up redis
```

Or use any local Redis 7 on port 6379. The backend defaults to `redis://localhost:6379/0`, so the `REDIS_URL` variable isn't needed for this route.

### API

```powershell
cd backend
uv sync
uv run uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

### Worker

```powershell
cd backend
$env:ANTHROPIC_API_KEY = "sk-ant-..."
uv run celery -A worker.app worker --loglevel=info --pool=solo
```

Celery's default prefork pool doesn't work reliably on Windows, so use `--pool=solo` (or `--pool=threads`).

### Frontend

```powershell
cd mobile/ML-Rock-Climbing-App
npm ci
npx expo start --host lan
```

Then scan the QR code with Expo Go. Other scripts: `npm run android`, `npm run ios`, `npm run web`.

Running Expo directly on Windows means it detects your real LAN IP itself, so `HOST_LAN_IP` isn't needed. On the web target, the API host falls back to `localhost`.

## Running the tests

From `backend/` (no Redis or Docker needed; the tests use fakes):

```powershell
uv sync --group dev
uv run pytest
```

See [testing.md](testing.md) for coverage and load testing.

## Troubleshooting

| Symptom | Likely cause and fix |
|---------|----------------------|
| Expo Go says "Could not connect to server" | `HOST_LAN_IP` is stale or the phone is on a different network. Run `scripts/refresh-lan-ip.ps1`. Check the firewall for port 8081. |
| App connects but every API call fails | Phone can't reach port 8000. Check the firewall, and confirm `HOST_LAN_IP` is your PC's address, not a Docker or WSL one. |
| No QR code in the frontend logs | The container has no TTY. Make sure `tty: true` is still set in `docker-compose.yml`, and set `EXPO_TOKEN`. |
| `POST /analysis` returns 409 | The same `Idempotency-Key` is still processing. Use a new key, or wait for the task to finish. |
| Analysis stays `PENDING` | The worker isn't running or can't reach Redis. Check `docker compose logs worker`. |
| Analysis fails with an authentication error | `ANTHROPIC_API_KEY` is missing or empty in `.env`. Recreate the worker: `docker compose up -d --force-recreate worker`. |
| Detection errors about the model file | `backend/models/best.pt` is missing. Add the weights or set `MODEL_PATH`. |
| `ImportError` for `libGL` in the backend | The image is missing OpenCV system libraries. Rebuild with `docker compose build api worker`. |
| Port already in use (6379, 8000, 8081) | Stop the other process using it, or change the host side of the port mapping in `docker-compose.yml`. |
| Changed `.env` but nothing changed | Compose reads `.env` when containers are created. Recreate them: `docker compose up -d --force-recreate`. |
